# AI-помощник для товарных описаний КИПиА

Прототип сервиса, который превращает JSON с данными контрольно-измерительного
прибора в черновик карточки товара для B2B-интернет-магазина.

**Стек:** TypeScript, Node.js 20+, Express, Zod, Google AI Studio (Gemini REST API),
ванильный HTML/CSS/JS, Vitest.

Краткое описание промптов и принятых решений — в
[`PROMPTS_AND_DECISIONS.md`](./PROMPTS_AND_DECISIONS.md).

```
JSON / веб-форма
      │
      ▼
Zod-валидация и нормализация ──► промпт + JSON Schema ──► Gemini 3.8 Flash
      │                                                        │
      │                                                        ▼
      └────────────── детерминированная проверка ◄──── JSON-ответ модели
                              │
                              ▼
              JSON / Markdown / текст для копирования
```

## Что реализовано

- приём товара через JSON API и веб-форму;
- генерация через Google AI Studio (Gemini);
- SEO-заголовок до 70 символов;
- SEO-описание 800–1200 символов;
- структурированный список характеристик;
- 3–5 поисковых запросов;
- коммерческий блок «кому подходит / какие задачи решает»;
- список отсутствующих данных и предупреждений автопроверки;
- JSON и Markdown на выходе, копирование и скачивание в UI;
- обработка невалидного JSON, пустых полей, ошибок и таймаутов API;
- запрет на выдуманные технические значения: проверка ответа по входным данным;
- CLI для пакетной подготовки примеров и тесты.

## Быстрый старт

Требуется Node.js 20+.

```bash
npm install
cp .env.example .env
```

Получите ключ в [Google AI Studio](https://aistudio.google.com/apikey) и положите его
в `.env`:

```dotenv
GEMINI_API_KEY=ваш_ключ
# или GOOGLE_API_KEY=ваш_ключ
GEMINI_MODEL=gemini-3.8-flash
```

Запуск:

```bash
npm run dev
```

Откройте <http://localhost:3000>. Ключ используется только на сервере: в браузер он
не попадает, в коде и репозитории его нет. `.env` добавлен в `.gitignore`.

### Запуск без ключа

Для проверки UI и CLI без обращения к Google:

```bash
LLM_PROVIDER=mock npm run dev
# или
npm run generate -- --input samples/manotom-dm02.json --provider mock
```

Mock-провайдер собирает шаблонный, но безопасный ответ из входных данных. Он нужен
для тестов и демонстрации; реальное качество текста даёт Gemini.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `GEMINI_API_KEY` / `GOOGLE_API_KEY` | — | ключ Google AI Studio; обязателен для `LLM_PROVIDER=gemini` (поддерживаются оба имени) |
| `GEMINI_MODEL` | `gemini-3.8-flash` | модель Gemini |
| `LLM_PROVIDER` | `gemini` | `gemini` или `mock` |
| `GEMINI_API_BASE` | `https://generativelanguage.googleapis.com/v1beta` | базовый URL REST API |
| `PORT` | `3000` | порт веб-сервера |
| `REQUEST_TIMEOUT_MS` | `60000` | таймаут одного запроса к Gemini |
| `MAX_RETRIES` | `2` | число повторов при 408/429/5xx и сетевых ошибках |
| `TEMPERATURE` | `0.3` | температура генерации |
| `MAX_OUTPUT_TOKENS` | `4096` | лимит токенов ответа |

## API

### `POST /api/generate`

Принимает товар напрямую или в обёртке `{ "product": { ... } }`.

```bash
curl -X POST http://localhost:3000/api/generate \
  -H 'Content-Type: application/json' \
  --data @samples/manotom-dm02.json
```

Формат входа:

```json
{
  "name": "Манометр показывающий DM 02",
  "manufacturer": "Манотомь",
  "specs": {
    "диапазон измерений": "0–1,6 МПа",
    "класс точности": "1,5",
    "присоединение": "G1/2",
    "диаметр корпуса": "100 мм"
  },
  "description": "Прибор предназначен для измерения избыточного давления."
}
```

Формат ответа (сокращён):

```json
{
  "product": { "name": "...", "manufacturer": "...", "specs": {}, "description": "..." },
  "draft": {
    "seoTitle": "...",
    "seoDescription": "...",
    "keySpecs": [{ "name": "диапазон измерений", "value": "0–1,6 МПа" }],
    "searchQueries": ["...", "...", "..."],
    "commercialBlock": { "suitableFor": "...", "tasks": ["..."] },
    "missingData": ["..."]
  },
  "quality": {
    "titleLength": 38,
    "titleLimit": 70,
    "descriptionLength": 1010,
    "descriptionRange": { "min": 800, "max": 1200 },
    "searchQueriesCount": 4,
    "specsWithMissingValues": 0,
    "warnings": [],
    "needsReview": false
  },
  "meta": {
    "provider": "gemini",
    "model": "gemini-3.8-flash",
    "attempts": 1,
    "elapsedMs": 3400,
    "generatedAt": "2026-11-03T10:00:00.000Z"
  }
}
```

Дополнительно:

- `POST /api/generate?format=markdown` или заголовок `Accept: text/markdown` —
  Markdown-текст;
- `POST /api/generate?include=markdown` — JSON плюс поле `markdown` (так делает веб-форма,
  чтобы не вызывать модель дважды);
- `GET /api/health` — состояние сервиса и настроена ли LLM.

### Ошибки

| HTTP | Код | Когда возникает |
| --- | --- | --- |
| 400 | `INVALID_JSON` | тело запроса не парсится как JSON |
| 400 | `INVALID_INPUT` | нет `name`, неверные типы, пустые обязательные поля |
| 413 | `INVALID_INPUT` | тело больше 1 МБ |
| 422 | `LLM_BLOCKED` | Gemini заблокировал запрос по safety-политике |
| 502 | `LLM_HTTP_ERROR` | ошибка Gemini API |
| 502 | `GENERATION_FAILED` | модель не вернула валидный JSON после повторов |
| 503 | `LLM_CONFIG` | не задан `GEMINI_API_KEY` |
| 504 | `LLM_TIMEOUT` | Gemini не ответил за `REQUEST_TIMEOUT_MS` |

Пример ошибки:

```json
{
  "error": {
    "code": "INVALID_INPUT",
    "message": "Некорректные входные данные товара",
    "details": [{ "path": "name", "message": "Поле name обязательно" }],
    "requestId": "..."
  }
}
```

## Как устроен промпт

Краткая версия промптов и решений также вынесена в
[`PROMPTS_AND_DECISIONS.md`](./PROMPTS_AND_DECISIONS.md).

Полный текст — в `src/prompts/productCard.ts`. Ключевые решения:

1. **Роль и аудитория.** Модель — технический контент-редактор B2B-каталога КИПиА;
   текст пишется для снабженца и контент-менеджера, а не для конечного потребителя.
2. **Один источник фактов.** Во входе есть только `name`, `manufacturer`, `specs`,
   `description`. Промпт прямо запрещает добавлять материалы, сертификаты, поверку,
   гарантию, IP, температурные диапазоны, совместимость и области применения, которых
   нет во входе.
3. **Дословные значения.** Значения характеристик нужно копировать без пересчёта
   единиц, округления и «уточнений». Это же проверяется после ответа.
4. **Структурированный вывод.** Используется `responseMimeType: application/json` и
   `responseJsonSchema` — модель возвращает объект по схеме, а не текст с Markdown.
5. **Длины.** В промпте указаны жёсткие границы (70 / 800–1200) и целевой объём
   900–1100 символов, чтобы модель не попадала ровно на границу. Длины проверяются
   детерминированно.
6. **`missingData`.** Модель обязана перечислить, каких данных не хватает. Дополнительно
   сервис сам считает отсутствующие поля: производитель, характеристики, описание,
   слишком короткое описание.
7. **Ремонтный проход.** Если ответ нарушает длины, количество запросов или содержит
   значение не из входа, сервис делает ещё один запрос с перечнем конкретных проблем
   и предыдущим JSON. Максимум одна попытка исправления, чтобы не раздувать стоимость.
8. **Температура 0.3.** Достаточно вариативности для текста, но меньше риска
   «додумывания»; значение настраивается через env.

### Как гарантируется отсутствие выдуманных характеристик

Защита многослойная:

1. **Промпт** запрещает новые факты и требует дословные значения.
2. **JSON Schema** фиксирует поля и не даёт модели вернуть произвольную структуру.
3. **Пост-проверка `reconcileDraft`.** Каждое значение из `keySpecs` сравнивается с
   нормализованными значениями из `specs` и `description`. Если значения нет во входе,
   оно заменяется на `«данных нет»`, а в `quality.warnings` попадает причина.
4. **Полнота.** Все характеристики из `specs` гарантированно попадают в `keySpecs`,
   даже если модель их пропустила.
5. **Противоречия.** Если модель пишет `«данных нет»` для характеристики, которая есть
   во входе, такая запись удаляется, а значение берётся из входа.
6. **Отсутствующие поля** считаются кодом, а не моделью, поэтому они не зависят от
   галлюцинаций.

Важное ограничение: коммерческий текст и SEO-описание проверяются только на длины,
а не на каждое утверждение. Формулировки вроде «подходит для ЖКХ» могут быть
обобщением, поэтому перед публикацией нужна вычитка человеком. Технические значения
при этом защищены строгой проверкой.

## Проверка

```bash
npm test          # 43 теста
npm run typecheck # tsc --noEmit
npm run build     # сборка в dist/
npm start         # запуск собранного сервера
```

Тесты покрывают:

- валидацию и нормализацию входа;
- разбор ответа модели;
- замену выдуманных значений;
- добавление пропущенных характеристик и запросов;
- обрезку заголовка и описания;
- retry/timeout/ошибки Gemini (с подменой `fetch`);
- HTTP-коды, Markdown, `include=markdown`, health, 404;
- ремонтный проход и поведение при сбое повторного запроса.

## Ограничения и что можно улучшить

- **Один товар за запрос.** Нет batch-эндпоинта; примеры генерируются скриптом
  последовательно. Для каталога нужен queue/worker и ограничение параллелизма.
- **Нет БД, CMS, авторизации и rate limiting.** По условию задания это не требуется,
  но для продакшена нужно добавить.
- **Нет кэширования.** Одинаковые запросы заново обращаются к Gemini. Можно кэшировать
  по хешу входа и версии промпта.
- **Строгая проверка значений.** Склеенные значения («24 В, 4 канала») или
  переставленные единицы могут быть заменены на `«данных нет»` — это безопаснее
  галлюцинации, но требует ручной правки. Улучшение: передавать в промпт ID
  характеристик и принимать `specId + value`.
- **Коммерческий блок не проверяется по смыслу.** Нужна вторая LLM-проверка с
  цитатами-источниками или ручная вычитка.
- **Качество SEO не измеряется.** Нет частотности, конкуренции и оценки выдачи.
  Можно подключить Wordstat/Keyword Planner и A/B-тесты.
- **Только русский язык.** Локализация не реализована.
- **Нет изображений и медиа.** Карточка текстовая.
- **Один провайдер.** Интерфейс `LlmClient` позволяет добавить OpenAI/Anthropic/
  локальную модель, но сейчас реализованы Gemini и mock.
- **Нет стриминга.** Для длинных ответов можно включить SSE и показывать прогресс.
- **Нет набора эталонных карточек.** Для системной оценки качества стоит собрать
  golden set и проверять регрессии промпта в CI.
